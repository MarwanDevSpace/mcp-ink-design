# Security & Trust Boundaries — mcp-ink-design

## 1. Threat Model

`mcp-ink-design` operates locally as a child process of the client IDE or AI tool (e.g. Claude Desktop, Cursor, Antigravity) over standard input/output (`stdio`).

### Potential Attack Vectors & Controls:

| Risk Area | Vector | Mitigation in mcp-ink-design |
|---|---|---|
| Malicious Input Injection | Large or malformed JSON payloads sent to tool invocations | Strict validation at protocol boundary via Zod schemas (`contracts/index.ts`). |
| Child Process Subversion | Python execution hijacking | Python runner executes strictly with an explicit argument list `["-m", "python.ink_verifier.cli", ...]`. No shell interpolation (`shell: false`). |
| Code Execution via eval | Evaluated client code | All JS/TS templates generated by the server avoid `eval()`, `Function()`, and raw `innerHTML` sinks. |
| Insecure Auth Storage | Secrets in client code | Tool rules flag `localStorage` JWT storage and recommend HttpOnly cookies. |
| Denial of Service | Infinite loops in child process | Hard timeout (12,000ms) with automatic process termination on Python bridge calls. |
| Information Disclosure | Leaking secrets or credentials in logs | Logger writes only safe metadata to `stderr`. No payload dumps or system tokens. |

## 2. Content Security Policy (CSP) Standard

The server generates and recommends the following default strict CSP:
```text
default-src 'self';
script-src 'self' 'nonce-{RANDOM}' https://cdnjs.cloudflare.com;
style-src 'self' 'unsafe-inline' https://fonts.googleapis.com;
font-src 'self' https://fonts.gstatic.com data:;
img-src 'self' data: https:;
connect-src 'self';
frame-ancestors 'none';
base-uri 'self';
form-action 'self';
```
